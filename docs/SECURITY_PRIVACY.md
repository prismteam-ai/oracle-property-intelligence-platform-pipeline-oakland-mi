# Security and privacy

Approved public artifacts, protected runtime projections, private working intake and CRM operational records have distinct boundaries. Raw owner/contact/provider records remain private and do not enter Git, logs, public artifacts or release media. No source field is fabricated to close an unmet outcome. [Coverage](DATA_COVERAGE.md) and [known limitations](KNOWN_LIMITATIONS.md) preserve the evidentiary limits.

## Review access

The operator delivers a dedicated low-privilege capability separately. It creates expiring signed sessions with server-side revocation and enables bounded protected projections and isolated lead workflows, not administration, acquisition, publication or outreach. Treat a capability intentionally shared with evaluators as publicly knowable: isolation, quotas, finite retention and rotation remain required. Privileged credentials, signing keys and live session tokens never belong in the repository, public evidence or demo.

Payload limits, origin checks, snapshot binding and deterministic factual validation remain enforced. One-hour sessions, capability-until-rotation and endpoint/map retention are separate controls. [The evaluator guide](EVALUATOR_GUIDE.md) explains denial and recovery without an AWS login. Temporary deployment access is separately scoped and closed after release work; retaining hosted review does not retain that authority.

## Infrastructure and telemetry

Private encrypted S3 uses OAC, TLS and public-access blocks. Runtime IAM is limited to the exact snapshot prefix, access secret and session/quota keys. Infrastructure has task tags, active X-Ray and 90-day logs. The alert function can read only its routing secret and cannot query county data. The finite map key keeps the exact CRM origin, read-only tile action and provider restriction.

Powertools records bounded operation/status/latency values. Request/response bodies, cookies, query inputs, source rows and raw exceptions stay out of logs/trace metadata. Metrics use service dimensions to bound privacy exposure and cardinality. PagerDuty delivery contains a fixed operational summary and hashed alarm correlation key, without raw alarm reasons or account identity.

## Release review

`pnpm scan:source` is a high-confidence key/bulk-artifact/TypeScript-pattern check, not exhaustive secret detection. Exact private-value/source scans, expanded package review, owner/source adjudication, screenshot/OCR/pixel review, independent code review and sealed archive verification are separate evidence. Review sanitized media for accidental disclosures before local delivery; recording permission does not authorize upload or employer communication.

Preserve failed attempts and exact comparison identities. Close temporary credentials and verify revocation; perform scoped local census/sanitation against the approved comparison reference. State exclusions explicitly rather than claiming whole-home, process-memory or SSO-store coverage. The final external receipt records actual scope and result; a source checkout or older successful scan does not certify new payload bytes.
