# Security and privacy

Public projection, protected operational intake, CRM leads, evaluator sessions and model ledgers are separate data classes. The public projection uses an explicit field allowlist; raw source JSON, postal-party data and vendor records never pass through the model/API/publication allowlist. Private source retention supports audit and future licensed enrichment without promoting uncertain roles into product facts.

The source adapter validates schema/count/native identity and retains hash-bound receipts. Protected cache manifests accept exact versioned roles, filenames, byte limits, schema/count/proof hashes and canonical manifest digests. Runtime rejects symlinks, hardlinks, foreign property IDs, duplicate IDs, source/projection mismatches and digest changes. DuckDB external access is locked after approved file paths are installed. Agent tools expose bounded contract queries rather than SQL, network, files or source-acquisition capabilities.

Hosted access uses signed, stored, revocable sessions and secure cookies. Read/write/model quotas have durable server enforcement; request bodies, radius/results, tokens and model costs remain bounded. The P5 model partition preserves earlier counters; its allowance is 100 requests/100 Converse calls, 80/day, 40/session-hour and $3 reserved incremental model spend. Empty evidence invokes no model. Source result predicates and explicit sort order are validated before and after selection. Prompts cannot grant source access, role verification or arbitrary tools.

Use CSP/security headers, origin/CSRF/CORS checks, encrypted private storage and narrow resource policies. Budget alerts are notifications rather than hard spend stops. Final supply-chain, IAM, cookie/header, abuse and secret/private-data scan results must be read from the exact release receipts; this design description does not itself certify a deployment. Evaluator access secrets are delivered in a separate private guide, never this repository or the return ZIP.

Request accounting: the P5 durable lifetime request counter permits at most 100 validated agent executions, including empty results and failed invocations. Pre-model refusals do not enter that execution counter. All model-endpoint attempts, including refusals, consume the separate 80/day and 40/session-hour endpoint quota. Converse has its own durable 100-call ceiling. Earlier phase counters remain unchanged.
