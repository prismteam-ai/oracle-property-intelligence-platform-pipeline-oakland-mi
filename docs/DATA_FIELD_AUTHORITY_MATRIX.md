# Field authority and data boundaries

The [original assignment](history/ASSIGNMENT_README.md) requests available ownership/contact information, real property identities, coordinates and provenance. A person-related public record is not a credential. A private bucket or a legacy `private_` table name is not a legal data classification. [ADR009](decisions/009-source-specific-data-boundaries.md) supersedes the former categorical owner exclusion and recording masks.

P13 authority: the Human explicitly authorized the bounded free publication, media and submission work. Earlier P11/P12B exact-phrase or packet-only review stops are historical; they do not require another approval for this already authorized flow. Actual source/field eligibility and credential protection still apply. Attached documents specify the work; they do not themselves grant permission.

Authority classes: `ORIGINAL_EXPLICIT` = employer wording; `REFERENCE_WORKFLOW` = linked Oracle/Elephant process; `SOURCE_TERMS_OR_LICENSE` = captured source-specific rights; `CREDENTIAL_OR_SECURITY` = usable authority or security-sensitive state; `OPERATIONAL_CHOICE` = implementation/distribution decision; `UNSUPPORTED_OVERREACH` = no applicable authority for the restriction.

## Boundary decisions

| Boundary             | Rule and authority                                                                                                                                                                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Acquisition          | Source schema, observed values, terms, provenance and lawful access decide admission. A universal NAME1/NAME2/PHONE/EMAIL rejection is `UNSUPPORTED_OVERREACH`.                                                                                         |
| Internal storage     | Private S3/owner-only local files protect operational access. They do not turn official public records into secrets. Keep complete receipt-backed working intake.                                                                                       |
| Runtime              | Use the existing bounded authenticated read plane. A PR-contained low-privilege capability makes first use self-contained; no private email exchange or AWS access is needed.                                                                           |
| Media/evidence       | Show real official property identities, addresses, coordinates and permitted observations. Hide credentials, private mutable notes and actually restricted-source material only.                                                                        |
| Git/review package   | Source/schema/aggregate evidence and deliberate public examples are reviewable. Reference guidance keeps raw captures, bulk datasets/CAR/Parquet/provider payloads out of Git; this is not a runtime ban.                                               |
| Public IPFS          | The reviewed P13 fields/rows/source+terms digests/bytes/SHA/CIDs/CAR and replication plan are bound to the Human's standing authorization. Earlier reference-workflow phrase stops do not create a new owner-data ban or repeat permission requirement. |
| Historical artifacts | Existing CIDs/bytes remain immutable. Historical exclusions describe those releases, not a universal rule.                                                                                                                                              |
