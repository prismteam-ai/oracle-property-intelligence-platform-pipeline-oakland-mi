# Observability and alerting

Every Lambda entrypoint uses Powertools Logger, Tracer and Metrics. The read API and alert notifier have active X-Ray and explicit 90-day log groups. Logs contain bounded operation, status and latency; event logging and response/error trace capture are disabled.

Namespace: `PrismAssessment`. Service: `prism-oracle-review` or `prism-oracle-alerts`. Custom metrics have service-only dimensions. They cover request count/latency/errors, auth failures, rate limits, query latency/result count, snapshot validation/unavailability and observed source coverage. Counts describe the validated loaded snapshot. SourceFreshnessKnownCohorts and SourceFreshnessUnknownCohorts distinguish known reported data-through dates from unknown public/legacy groups. SourceDataThroughAgeUpperBoundSeconds uses the oldest known date at UTC midnight as a conservative date-granularity upper bound. It is omitted when all groups are unknown; capture times never substitute for data-through dates, and the gauge does not claim universal county freshness. Producer request/rate-limit/failure receipts remain in the bounded acquisition journal.

The CDK dashboard shows request/access signals, latency, errors and source counts. Lambda/API errors, throttling, latency and caught application errors have alarm and recovery routes to a bounded notifier. The notifier reads one Secrets Manager routing key, uses PagerDuty Events API v2, preserves a hashed dedup key for trigger/resolve, has a two-second per-call timeout and at most three attempts with bounded backoff/jitter. Runtime/network output is not copied into provider payloads.

The integration is disabled until a candidate-controlled free account exists and a private routing secret is configured. Disabled mode returns `EXTERNAL_ORGANIZATION_DEPENDENCY_BLOCKED` and makes no secret or provider call. Local injected transport tests are distinct from a live synthetic trigger/resolve receipt. Internal organization dashboard registration is prepared separately; no supplied access means it is not claimed applied.

Metrics, dashboards, alarms, logs, traces and retained resources can incur charges. Low-cardinality metrics and explicit limits reduce cost; they do not guarantee zero cost or an immediate billing stop. See [deployment](DEPLOYMENT.md).
