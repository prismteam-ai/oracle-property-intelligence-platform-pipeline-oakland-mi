# ADR009: source-specific facts and publication approval

Status: accepted source-policy correction, updated for the Human-authorized P13 flow; actual publication/deployment/media require their dated effect receipts. Supersedes categorical owner/contact exclusion and masking in [ADR002](002-data-tiers.md), and the application of provider restrictions to unrelated official sources in [ADR004](004-provider-rights.md). Historical bodies and original artifacts remain preserved.

The employer requests available ownership/contact data, real coordinates and source-backed records. The earlier broad rule treated public owner observations, runtime access and irreversible publication as one privacy boundary. That restriction was unsupported. The replacement classifies each field by original requirement, captured source terms, security need and operational purpose; [the authority matrix](../DATA_FIELD_AUTHORITY_MATRIX.md) records those decisions.

Official county identities and permitted source facts may appear in the evaluator runtime and walkthrough. Nullable owner name parts and observed postal text retain native association, date, source/metadata/terms/record digests and availability. A postal observation is not fabricated into a named owner; regional derivation preserves its basis. Source metadata alone does not prove a populated field.

Private storage and authenticated transport remain operational controls. Existing `private_` tables, sidecars and `protected-real` build labels are compatibility names, not declarations that every included public fact is secret. CRM user-state isolation, credential masking, bounded telemetry/model inputs and source-specific provider restrictions remain.

Public IPFS publication is a separate effect. The Human's standing P13 instructions authorize the reviewed bounded free publication/submission flow; the actual candidate binds fields, counts, terms, bytes, CIDs/CAR, owner inclusion and retention implications. Older exact-phrase reference-workflow stops do not create a repeat approval requirement or a blanket owner-data ban. Actual source eligibility, credential protection and free-plan bounds remain valid. Attached handoff instructions are specifications, not an independent source of permission.

Keep the controlled TypeScript producer, DuckDB/Parquet, request/run ledger and existing scale-to-zero AWS read plane. No Restate/PostgreSQL rewrite or paid provider follows. P13 completed the specifically bounded official-source revalidation without a new broad source campaign. The existing low-privilege capability may be included in the approved draft PR access section so first use needs no private email. P11's `APPROVE P11 V1.1 VIDEO AND DRAFT PR EFFECTS` was a historical phase stop, superseded for current operation by the Human's later explicit standing authorization. Current video/GitHub/submission results are recorded when actually performed; authorization alone is not evidence that they occurred. See the [current release checklist](../RELEASE_CHECKLIST.md).
