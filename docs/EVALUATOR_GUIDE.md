## Access and quota

The capability permits bounded protected projections and isolated lead workflows. It grants no administration, source acquisition, publication or outreach. Expired/revoked sessions deny protected reads. Oracle health reports access mode `review`; CRM reports `review-session`. These valid names differ.

Agent limits are shared across operator, media and evaluator use: **120 model reservations total, 80 per UTC day and 40 per session-hour**; validated requests are 200 total, 160 per UTC day and 40 per session-hour, with a separate 240/day endpoint cap. At the accepted 2026-10-29 snapshot, 77 total / 76 that UTC day left **43 total / 4 that day**. Later use consumes those balances. A new session or deployment never resets them. Use the latest dated quota receipt rather than assuming that historical headroom is still available.

## Failure recovery

- **401:** the one-hour session may have expired. Sign in again with the current capability. A rotated/revoked capability must remain denied; it is not an AWS login problem.
- **429:** stop repeated agent requests. Respect the applicable UTC-day/session/total limit and the dated headroom; a new browser does not create more quota.
- **Loading or map failure:** let the bounded cold request finish, then refresh once. Verify HTTPS and the release access sheet's retention date. Do not replace map keys or enter privileged credentials.
- **Persistent failure:** retain the time, step and safe error/status or snapshot identity. Exclude the capability, cookies, source rows and screenshots of private details. This guide does not require cloud troubleshooting by the evaluator.
