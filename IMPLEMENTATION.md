# Delivered implementation

Oracle separates controlled source acquisition from an authenticated, scale-to-zero read plane. The producer validates receipts, reconciles properties and preserves immutable run history; native DuckDB serves bounded queries and MCP from pinned public artifacts and protected observation sidecars. The CRM consumes the versioned contract rather than reacquiring source data. The [original assignment](docs/history/ASSIGNMENT_README.md) remains readable and controlling.

The admitted county snapshot contains 490,775 parcel records and 559,701 site-address records, reconciled into 490,799 canonical properties. The protected companion retains 39,282 normalized permit observations, 3,747 reported-owner observations and 669 building-year observations across 659 distinct nonconflicting properties. These are observation counts. [Coverage](docs/DATA_COVERAGE.md) defines their dates, joins and evidentiary limits; [known limitations](docs/KNOWN_LIMITATIONS.md) is the canonical source-outcome disclosure. No paid subscription is required, purchased or needed for these admitted inputs.

The delivered infrastructure uses task-scoped CDK assets and deployment roles, immutable checksum-staged data, neutral review stacks, 90-day logs, active X-Ray/Powertools and bounded alert delivery. Query loading, source projections and UI panels have explicit module boundaries. The accepted technical release also includes finite map-expiry validation and CloudFormation `ForceUpdate` for a recently used key, preserving its origin/action/provider restrictions. Architecture, contract 0.5.0 and reviewed v8 data remain frozen during release assembly.

The accepted technical evidence dated 2026-10-29 binds Oracle `6d14d60` and CRM `f40b75a` to deployed packages, four fresh browser contexts, API/MCP, actual map rendering and the full grounded-agent workflow. The strict Novi example produced 648 matches / 50 returned using a disclosed building-year proxy and the unchanged age-greater-than-15 predicate. Exact pins and acceptance digest are in [release status](docs/RELEASE_STATUS.json). Any later source is accepted only through its own external receipt matched to runtime identity; the earlier result is not silently inherited.

Historical public CIDs, full private working intake, original 114-row traceability and earlier failed attempts remain preserved. Current local CLI/Atlas compatibility is distinct from external publication. [Testing](docs/TESTING.md), [publication](docs/IPFS_PUBLICATION.md) and the [release checklist](docs/RELEASE_CHECKLIST.md) explain those boundaries. Local media preparation and later GitHub/submission effects have separate authorization and evidence.
