# Current official public profile

This profile adds a versioned current public dataset without changing the historical nine-file snapshot loader or prior CIDs. It exports all admitted official permits and building-year observations, property/address associations, source-native match dispositions (including held Troy records), qualified owner/deed observations, provenance and ordinary offline DuckDB query macros. Commercial-provider observations and operational run/session data are separate inputs and are rejected by this builder. Historical `private`/`protected` storage names do not themselves decide official-source publication rights: the explicit source policies and captured source evidence do.

`official_source_intake_dispositions` preserves all twelve Troy report fields under their actual source roles, plus native identity, digest/receipt, observation date, association and join reason. An Applicant remains a reported applicant; it is not asserted to be an owner, verified job contractor, licensed company or BBB-rated business. The issued-event report does not expose an authoritative current lifecycle status, so that field remains null. A missing original source-schema receipt remains null and does not discard the row.

The two reviewed Independence notes are separately versioned, digest-bound observations. The explicit closeout date is inspectable there. Canonical V9 permit dates, including the old null `closedAt`, remain unchanged so the live and public working projection agree. Building year is a building-age proxy rather than roof installation evidence. Issue age is not continuous-open duration. Recorded-index gaps retain the original bounded observed-through dates and do not establish legal ownership continuity.

## Build and freeze

Use the lockfile-pinned dependencies and Node24 runtime; do not install or upgrade services. Each CLI is plan-only unless `--execute` is present.

1. `node --import tsx scripts/build-current-publication.ts --execute --input SOURCE_BUILD_INPUT.json` verifies existing source artifacts and source policies, derives the current Parquets, reconciliation, schema, source/run history and a local intermediate package. This has no network/upload effects. Its intermediate DuckDB is not the release canonical database.
2. Freeze the source commit/tree, relevant source-file hashes and all public input-file hashes. Construct a public-only input folder containing the fifteen required logical-relation Parquets and `artifact-index.json` with version `p13-public-build-input-index-v1` and their exact names/bytes/SHA-256 values. Preserve the separate official raw factual source Parquet and other publication metadata in the source package.
3. `node --import tsx scripts/isolate-current-public-database.ts --execute --directory FROZEN_INPUTS --index-sha256 INPUT_INDEX_SHA256 --output-directory CANONICAL_OUTPUT` constructs the first canonical DB in bubblewrap. Only reviewed source/runtime/dependency files and the fifteen public Parquets/index are mounted read-only; an owned output directory and temporary directory are writable. Home, AWS, GitHub, original source/provider and CRM data roots are absent. The worker proves a separate network namespace and `ENETUNREACH` for a direct connection attempt. The environment is cleared and explicitly bounded; bubblewrap's `PWD=/app` is checked.
4. Save the worker JSON proof. It independently exports every complete logical relation from the constructed DB and compares the canonical Parquet bytes, records every row count, full table/view/macro definitions and column types/nullability, and computes the catalog hash. Freeze the resulting DB bytes; never reopen them for writing.
5. `node --import tsx scripts/finalize-current-publication.ts --execute --input FINALIZE_INPUT.json` checks the frozen source files and canonical proof, creates two clean directory/CAR wraps from the **same frozen bytes**, and requires identical file CIDs, root CID and exact CAR SHA-256. It uses immutable hardlinks within the same filesystem to avoid large duplicate payload copies. The separate `upload` folder contains exactly the DAG files: do not upload a wrap directory that also contains its CAR or outer manifest.
6. An independent reviewer must reopen the frozen DB read-only, verify schema/data/provenance/query and reconciliation parity, and verify the DB hash is unchanged. Publication requires actual exact-byte retrieval from both independent public operators. No local build result claims those external effects.

`publication-manifest.json` is outside its own DAG. Its current-root and own-CAR descriptors cannot be inside the bytes defining that same root. `artifact-index.json` excludes its own CID/root; the exact CAR is published as a separate downloadable asset. Provider receipts and independent retrieval proofs describe actual later effects, rather than rewriting historical receipts.

## Reproducibility scope

The current DuckDB2 engine produces different unused string-buffer bytes on independent physical encodings, including in a measured uncompressed case. All real source-derived Parquets/SQL/metadata matched across the observed independent builds; their physical DB hashes did not. This is disclosed, not patched or mislabeled as a pass. The empty hash-pinned seed fixes the engine's random identifier only.

The canonical public-only worker uses normal supported AUTO/lossless compression; every complete logical relation must still match its exact canonical Parquet. The uncompressed intermediate source-projection DB is a disk-only development output and is not the public canonical binary.

The release contract is an immutable, exact-hash canonical public-only DB, complete logical source/Parquet/schema/query parity, and repeatable exact DAG/CAR wrapping from that same frozen file. A future physical re-encoding is a new binary artifact unless its full hash actually matches. The recorded P13 review adjudication separates this engine behavior from the original assignment's immutable IPFS/offline-query requirements.

The bounded regression fixture covers source/provider rejection, ordinary runtime locking, pre-lock callback cleanup, download integrity/bounds/cleanup, retained unmatched native identities with null schema, and ordinary offline queries. Set `PRISM_RUN_PUBLICATION_ISOLATION_TEST=1` for the actual Linux bubblewrap/network/file-isolation and canonical/two-wrap integration test; normal application CI need not install bubblewrap.

Primary engine context: [DuckDB random database identifier implementation](https://github.com/duckdb/duckdb/blob/main/src/storage/single_file_block_manager.cpp), [upstream compressed-string slack report](https://github.com/duckdb/duckdb/issues/23382). The measured P13 uncompressed case is reported separately; the upstream report alone is not claimed to prove an identical root cause.
